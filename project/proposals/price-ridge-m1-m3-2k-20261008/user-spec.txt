PRICE 방법 명세: ridge writer 고정과 수정 M1–M3
2026년 10월 8일 · @Jang Hyunjun
요약
writer는 모든 모델에서 ridge(MEMIT)로 고정하고, 현재 method에 수정 세 가지를 더한다. 세 수정은 Llama3에서 발동하지 않거나 같은 값이 된다. 그래도 Llama3, GPT-J, GPT2-XL 모두 이 명세로 2K까지 새로 실행하며, Llama3는 기존 결과(RS 99.8 / PS 91.2 / NS 84.9)와 같게 나와야 한다.

기대 수준은 Llama3 유지, GPT-J는 NS 우위, GPT2-XL은 MEMIT 계열 수준이다. GPT2-XL에서 AlphaEdit-BLUE를 넘는 것은 이 명세의 목표가 아니다.
ridge로 고정하는 근거는 Llama3 2K의 누설(이웃 프롬프트에서 new target의 NLL 하락)이다. ridge에서 ours의 누설은 MEMIT L4-only의 0.63배이고, AlphaEdit writer에서는 AlphaEdit L4-only의 1.12배다.
그대로 두는 것
writer, 가격, 예산, 목적함수, commit의 정의는 현재 코드와 같다. batch는 요청 B = 100개이고, r은 요청, l은 대상 층, a는 anchor(요청의 크기 기준)를 가리킨다.
Writer
층마다 ridge 해를 한 번 풀고, 편집은 요청 R을 그 해에 곱해 기록한다.
T_l = \lambda C_{0,l} + H_l + K_l K_l^{\top}, \qquad Q_l = T_l^{-1} K_l, \qquad \Delta W_l = R_l Q_l^{\top}
• K는 요청별 mean key다. prefix 없는 문맥 하나와 prefix 문맥 5개의 평균을 0.5씩 섞는다.
• C0는 native 통계의 토큰 2차 모멘트이고, H는 지금까지 commit된 mean key의 외적 합이다.
• M = QᵀK의 대각 M[r,r]이 요청 r의 실현 비율이다. 요청 norm 중 실제 응답으로 나오는 몫을 뜻한다.
가격
같은 batch의 다른 요청에 미치는 반응 크기를 층별로 재고, 요청마다 가장 싼 층을 1로 둔다.
X_l[r,j] = \frac{a_{lr}}{a_{lj}} \cdot \frac{M_l[r,j]}{1 - M_l[j,j]}, \qquad
\kappa_{lr} = \sqrt{\frac{1}{B-1} \sum_{j \neq r} X_l[r,j]^2}, \qquad
\pi_{lr} = \frac{\kappa_{lr}}{\min_{l'} \kappa_{l'r}}
batch 진입 시 한 번 계산하고 그 batch 동안 고정한다. 추가 forward나 solve는 없다.
예산과 확장
\sum_l \pi_{lr} \frac{\lVert R_{lr} \rVert}{a_{lr}} \le \beta_r, \qquad \lVert R_{lr} \rVert \le 0.75\, a_{lr}
\beta_r = \beta_{\mathrm{base}} \left( \frac{\beta_{\max,r}}{\beta_{\mathrm{base}}} \right)^{s_r/4}, \qquad
\beta_{\max,r} = \max\left( \beta_{\mathrm{base}},\; 0.75 \max_l \pi_{lr} \right)
• 주 arm은 CAP075다(β_base = 0.75, 층별 cap 있음). CAP100과 FREE100은 ablation으로만 쓴다.
• 확장 단계 s는 0에서 시작한다. grace가 지난 뒤 F ≥ 0.05인 update마다 1씩 올라 4에서 멈춘다.
목적함수와 optimizer
F_r = \frac{1}{6} \sum_{c=1}^{6} \mathrm{NLL}\left( o_r^{*} \mid x_r^{c} \right) + 0.0625\, \mathrm{KL}_r, \qquad
J = \sum_r \left( F_r + \frac{0.5}{a_{*r}^{2}} \sum_l \lVert R_{lr} \rVert \right)
• 손실은 실제로 기록될 응답으로 계산한다. 후보 가중치에서 key를 다시 계산하고, 그 응답을 subject 마지막 토큰 위치에 주입한다.
• a*는 최상위 대상 층의 anchor다.
• optimizer는 EfficiencyAdam이고 lr은 native 값이다. 매 step 뒤 예산 집합으로 정확히 사영한다.
• 한 번 F ≥ 0.05가 된 요청은 끝까지 갱신한다.
Commit
마지막으로 평가한 후보를 그대로 기록한다. 그 뒤의 mean key로 모든 대상 층의 H를 갱신한다.
수정 세 가지
세 수정 모두 값 하나 또는 규칙 하나를 바꾸며, writer의 식과 가격·예산의 식은 건드리지 않는다.
M1. anchor guard
canonical 행(prefix 없는 원문)의 subject 마지막 토큰 위치가 0이면, anchor를 prefix 문맥 5개의 같은 층 hidden norm 평균으로 대체한다.
a_{lr} =
\begin{cases}
\lVert h_l(x_r^{\mathrm{canon}})[p_r] \rVert & p_r > 0 \\
\frac{1}{5} \sum_{c \in \mathrm{prefix}} \lVert h_l(x_r^{c})[p_r^{c}] \rVert & p_r = 0
\end{cases}
• 구현 위치: jlz_price_gptj/entry.py와 jlz_price_gpt2xl/entry.py의 prepare_entry. prefix 행의 hidden은 같은 forward에서 이미 잡히므로 추가 계산이 없다.
• 가격, cap, 예산 가중, norm 벌점은 모두 entry['anchors']를 읽는다. 이 한 곳만 고치면 네 곳에 함께 반영된다.
• Llama3 불변: 토크나이저가 BOS를 붙여 위치 0이 나오지 않는다.
• BOS가 없는 토크나이저에서는 문두의 단일 토큰 subject가 위치 0에 온다. 첫 2,000건 중 해당 batch는 B3, B5, B7, B10, B17, B20이다. B3의 Spain(P463)은 프롬프트를 복원하지 못해 추정이다.
관측 근거는 GPT-J에서 편집 직후 그 batch 이웃 1,000개의 평균 변화다.

M2. grace 규칙
K_grace를 update 수의 절반(내림)으로 둔다.
• 구현 위치: jlz_price_gpt2xl/profile.py의 K_grace=12를 (hp.v_num_grad_steps-1)//2로 바꾼다.
• Llama3와 GPT-J 불변: update 24회의 절반이 12라 지금 값과 같다.
• GPT2-XL은 update가 19회라 12에서 9로 바뀐다. 최대 예산에서 도는 update가 4회에서 7회로 늘어난다(Llama3는 9회).
• 관측 근거: GPT2-XL에서 CAP075와 CAP100은 평균 최종 예산이 약 1.0으로 비슷하다(추정). 그런데 확장을 탄 요청은 56% 대 32%이고, 2K 이웃의 true NLL 상승은 +1.96 대 +1.66이다.
M3. 실현 비율 하한
첫 batch의 최하층에서 실현 비율의 중앙값이 0.5 미만이면, 0.5가 되는 값까지 λ를 낮춘다. 0.5 이상이면 native λ를 그대로 쓴다.
m_0(\lambda) = \operatorname{median}_r\, M_{l_0}[r,r], \qquad
\lambda = \min\left( \lambda_{\mathrm{native}},\ \lambda_{1/2} \right), \qquad m_0(\lambda_{1/2}) = 0.5
절차는 다음과 같다.
1. 기존 entry-price.json의 B1, 최하층 denominator에서 1 − denominator의 중앙값을 읽는다. 새 계산이 필요 없다.
2. 0.5 이상이면 native λ를 유지하고 끝낸다.
3. 0.5 미만이면 W0에서 B1 key로 최하층만 다시 풀면서 λ를 이분 탐색한다. 중앙값이 0.5 ± 0.01에 들면 멈춘다.
4. 찾은 값을 profile의 lambda_C에 기록하고 실행 전체에서 고정한다.
• 의미: 예산이 요청 norm 단위이므로, writer가 요청의 절반 이상을 실현해야 0.75가 모델 간에 같은 뜻을 갖는다.
• Llama3 불변: L4의 실현 비율이 0.63~0.70으로 관측돼 발동하지 않을 것으로 본다. 0단계에서 로컬 값으로 확정한다.
• 관측 근거: GPT2-XL은 B1에서 base 예산으로 충족한 요청이 13%다(Llama3 87%, GPT-J 89%). 편집 유지도 나빠 R의 new NLL이 0.5K의 0.54에서 2K의 1.18로 오른다.
• 위험: 편집이 강해져 RS와 PS는 오를 가능성이 높지만, 이웃의 true NLL 상승이 줄지는 불확실하다. 그래서 1단계에서 M2와 분리해 시험한다.

batch 1회의 절차
한 batch는 진입 측정, 가격 고정, 반복 최적화, commit의 순서로 진행한다.
1. 진입 forward. 요청마다 rewrite 문맥 6개와 KL 문맥 1개를 통과시켜 층별 key와 hidden을 모은다. anchor를 계산하며 M1을 적용한다.
2. ridge 해. 층마다 λ·C0 + H를 분해하고 Q와 M을 구한다. λ는 M3로 정한 값이다.
3. 가격 고정. M에서 π를 계산하고 요청별 β_base와 β_max를 정한다. 이 batch가 끝날 때까지 바꾸지 않는다.
4. 반복. R = 0에서 시작해 평가 후보마다 아래를 수행한다.
    1. 후보 가중치에서 key를 다시 계산해 실현 응답을 구한다.
    2. 응답을 subject 위치에 주입해 F를 잰다. F ≥ 0.05인 요청을 활성화한다.
    3. 그 요청의 update 횟수가 K_grace(M2) 이상이고 여전히 F ≥ 0.05이면 확장 단계를 하나 올린다.
    4. 활성 요청만 Adam으로 갱신하고 예산 집합으로 사영한다.
5. Commit. 마지막 후보의 R로 각 층에 R·Qᵀ를 더한다.
6. history 갱신. commit 뒤의 mean key를 모든 대상 층의 H에 더한다.
7. 관측. 직전과 직후에 그 batch의 R, P, N을 재고, 0.5K마다 all-seen을 잰다.
검증 순서와 통과 기준
세 모델(Llama3, GPT-J, GPT2-XL) 모두 실행하고, 모든 실행은 2K까지 간다. 0단계의 두 항목 중 하나라도 어긋나면 해당 수정의 근거부터 다시 본 뒤 GPU 실행으로 넘어간다.
0단계: 기존 raw 확인
[ ] GPT-J의 위치 0 슬롯(B3/47, B5/36, B7/26, B10/25)에서 anchor가 batch 중앙값 대비 이상치인지 확인한다. 아니면 M1의 근거가 무너진다.
[ ] 세 모델의 B1 최하층에서 1 − denominator 중앙값을 읽어 M3 발동 여부를 정한다. Llama3는 0.5 이상이어야 한다.
1단계: ours 2K 본 실행 (세 모델)
주 arm은 CAP075이고 생성 지표(Fluency, Consistency)를 함께 잰다. 1K 값은 중간 점검으로만 쓰고 실행은 멈추지 않는다.
[ ] Llama3: 구성은 기존과 같다. 2K 실행은 약 5.1 GPU시간이다.
[ ] GPT-J: M1을 넣고, M3가 발동하면 함께 넣는다.
[ ] GPT2-XL: M1은 공통으로 넣고 M2만, M3만, M2와 M3 모두의 세 구성을 각각 2K까지 실행한다. 2K 실행 하나는 약 3 GPU시간이다.
통과 기준은 모델별로 다음과 같다.
[ ] Llama3: B1의 payload와 W 해시가 기존 run과 일치하고, 2K 결과가 기존 run(RS 99.80 / PS 91.18 / NS 84.94)과 같다.
[ ] GPT-J: 위치 0 batch의 직후 true NLL 변화가 BASE_ALPHAEDIT 대비 +0.1 이내다. 현행은 +0.1에서 +3.7이다.
[ ] GPT2-XL: 아래 표의 기준을 가장 많이 채운 구성을 최종 구성으로 정한다.
[ ] GPT2-XL의 어느 구성도 NS와 true NLL 기준을 못 채우면 native λ의 현행 결과로 보고한다.
