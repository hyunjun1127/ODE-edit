## Deliberate r2 registration

The original repair nonce remains the task identity and duplicate guard. One
new USER recall is admitted only with an immutable manual authority receipt,
bound to the exact prior r1 config/source/lock/submission, all seven terminal
job records, and the exact new `attempt-cache-repair-r2`. This is not an
automatic retry or a noCP model resume. Old source/raw/cost remain unchanged.
The observation-reuse `--old-attempt` remains the original `attempt-register-r1`,
not the failed cache-repair attempt.

Add `--manual-retry-authority <local/manual-retry-authority.json>` to the existing
`prepare` CLI, then run the existing CPU preflight and commit before `submit`.
The receipt and reconciliation are verified again at freeze, runtime and
collection. Reusing the same receipt after any new r2 registration is rejected.

Every new successor has an `afterok` technical completion prerequisite on the
primary. Other native-lane/resource frontiers use `afterany`; mixed clauses are
AND-composed. This is not a numerical quality gate. The five new successors use
`--kill-on-invalid-dep=yes`, so an impossible technical prerequisite becomes a
terminal scheduler state without GPU allocation or retry. The CPU failure
collector remains `afterany` all six. Exact dependency types, argv and source
bytes are inspected while held; unknown/OR syntax receives no concurrency
credit. The combined project/task GPU limit remains 2.
