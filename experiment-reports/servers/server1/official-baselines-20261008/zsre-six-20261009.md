# Llama3 zsRE native 6개 arm

직접 사용자 지시: `zsre도 6 arm 모두 제출하자.` 기존 official parent 안에서 FT/MEMIT/AlphaEdit/AlphaEdit-BLUE/MEMIT-FE/SPHERE, 각각 독립 cold first2000/BS100×20을 준비한다. server1 cap4, 기존 CF jobs/source/raw/CP 유지. zsRE에는 CF FLU/CON 설정·생성·점수·placeholder가 없다.

## 구현 및 실행 계약

- 새 task-private `zsre_run.py`, `zsre_prepare.py`; 알고리즘·hparams·요청 스키마는 동일 official registry다. Llama MEMIT과 AlphaEdit-BLUE는 target_new dict, 나머지 EasyEdit native는 문자열을 유지한다.
- FT L21, MEMIT/AlphaEdit/MEMIT-FE/SPHERE L4–8, AlphaEdit-BLUE L4/8. BLUE의 caller-owned H/P와 반환 H를 연결한다. 기존 P5층의 물리 slots0/4를 선택하며 원본 파일/solver/정밀도는 변경하지 않는다. 다른 native history는 기존 module-global H로 유지한다.
- 이번 새 source의 6개 zsRE chain은 단일 cold W0 prediction reference를 공유한다. CF generation READY나 과거 W0의 source identity를 새 source로 relabel하지 않는다. W0 `reference.evaluation`을 그대로 사용하며 별도 중복 W0 scoring을 하지 않는다. 참조 token/order/source/hash를 검증한다.
- 방법별 실제 zsRE B1 native smoke와 B3 연속 대 B2→fresh B3 resume 검증을 같은 qualification job의 독립 subprocess에서 수행한다. 각각 6 native batch calls이며 CF 편집/generation/pilot을 추가하지 않는다. GPU 실제 결과는 제출 전에 PASS라고 표시하지 않는다. 원독립 CF oracle parity와 zsRE resume evidence는 다른 검증이다.
- 본실행은 자기 qualification 성공 이후에만 시작한다. current/pre·post는 매 batch100, all_seen은 W5/10/15/20 실측이다. Specificity는 W0 prediction agreement, loc_ans는 별도 정확도다. 공통 `official_zsre_metrics` 및 공식 scalar-only transport를 사용한다.
- native W/H/RNG/context/cursor를 W0와 매batch 완료 후 latest1 checkpoint에 저장하고 W20을 보존한다. 이후 명시적 resume 연결을 제공하되 자동 retry는 없다. 원서버가 server1이므로 자체 CP는 현 경로에 보호하며 자기 자신을 사본으로 삭제하지 않는다.
- native apply/source/요청/weight-H 연속성, factual raw→summary/token denominator, 각 endpoint 및 W20 payload SHA를 own CPU collector가 재검산한다. actual GPU execution/remote W&B verification을 CPU receipt와 혼동하지 않는다.

## 자원 및 DAG

기존 owned admitted GPU frontier 전체 뒤에 새 W0를 연결하고, 네 개 lane으로 방법별 qualification→chain을 연결한다. 뒤의 두 lane 재사용은 afterany(resource), native 기술 prerequisite는 afterok다. 6개 production chain + 6개 qualification + W0 1개 + CPU collector 1개를 한 번 held 등록/검사/release한다. 기존 jobs mutation0, cap증액0, freeGPU polling0.

GPU1/CPU8/65536MiB/48h ceiling, collector GPU0/CPU8/24576MiB/4h. host disk/inode/512GiB output-reserve와 실제 node/QoS/combined cap을 등록 직전 검산한다. 실제 job IDs와 source/config lock은 제출 후 별도 영수증에 기록한다.
